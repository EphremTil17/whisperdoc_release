# WhisperDoc Technical Release Notes - v2.24.6
**Version Range: v2.23.6 to v2.24.6**

This release range moves WhisperDoc from a backend-only transcription model toward a more resilient **dual-path client architecture** while also modernizing the Flutter client’s storage and dependency foundation. The biggest visible change is the addition of a direct Groq Cloud transcription mode inside the Windows client, allowing speech-to-text to continue even when the WhisperDoc backend is unavailable, under maintenance, or intentionally bypassed.

At the same time, this range tightened the trust and runtime model around that new flexibility. OIDC discovery and issuer handling were hardened across the backend and clients, the Flutter transport path gained protocol-level keepalive behavior to better survive tunnel and idle conditions, backend upload validation and Parakeet startup costs were corrected in the right layers, and the local history system was migrated away from the unmaintained Isar stack to a Drift/SQLite implementation that better fits the project’s alpha-stage foundation goals.

The companion cleanup work in this range was substantial, but it was used to support the architecture rather than to become the story. Flutter service boundaries, widgets, settings flows, and tests were brought into line with the new model so the codebase reflects the intended final shape directly instead of preserving transitional compatibility behavior.

## Direct Transcription & Provider Flexibility (v2.24.0)

### Groq Cloud Direct Engine
- Added a complete client-side Groq transcription path under the Flutter client, including local PCM buffering, WAV packaging, multipart upload, typed HTTP error mapping, and rate limiting.
- This path works independently of the WhisperDoc backend, giving the desktop client a second operational transcription route rather than treating backend availability as a single point of failure.

### Mode-Aware UX and Configuration
- Updated the Flutter settings experience so users can explicitly switch between **WhisperDoc backend mode** and **Groq Cloud mode**, with the relevant credentials, language, and prompt options shown only when they matter.
- Reworked the Action Bar, Status Bar, Recording View, Connection mapping, and Profile Hub surfaces so provider identity and connection semantics remain truthful in each mode.

### Sanitization & Safety at the Client Edge
- Added a Dart-side text sanitizer mirroring the backend’s security posture so Groq responses are cleaned before reaching the UI, clipboard, or automation path.
- Enforced clearer local buffer and rate-limit behavior so long recordings, retry windows, and missing credentials fail in a user-facing and predictable way.

## Identity, Transport & Runtime Hardening (v2.24.1 to v2.24.3)

### OIDC Discovery and Principal Integrity
- Hardened OIDC discovery caching and issuer validation on the backend, and aligned both clients around `sub` as the canonical principal rather than treating human-readable fields as identity anchors.
- Tightened secret handling in the Flutter vault/settings path and updated profile surfaces so backend and Groq provider identity are presented more honestly.

### Transport & Upload Correctness
- Removed event-loop blocking from backend upload validation by moving file-size inspection into the already-offloaded temp-file persistence path.
- Corrected the issuer-verification flow to trust the discovery document’s issuer at signature-validation time rather than reusing an unverified token claim.
- Added protocol-level WebSocket ping behavior to the Flutter client so its long-lived connection semantics are closer to the Python terminal client under tunnels and idle periods.

### Runtime Efficiency
- Reduced Parakeet first-request penalties by front-loading FP16 conversion and CUDA JIT warmup at startup instead of paying those costs on the first real transcription request.
- Trimmed redundant sanitization and unnecessary serialization points in the backend transcription path so long-lived sessions behave more consistently under load.

## Data Layer Modernization (v2.24.4)

### Drift/SQLite History Store
- Replaced the old local Isar history implementation with a Drift/SQLite database stored under the application support directory and opened off-isolate for safer desktop IO behavior.
- Preserved the five-field local history model while moving storage operations onto typed Drift queries and companions, keeping consumer-facing history behavior stable at the app layer.

### Dependency Graph Cleanup
- Removed the unmaintained Isar toolchain and the unused `system_tray` dependency, which had been pinning the Flutter dependency graph to older build and analyzer paths.
- Refreshed the client dependency tree around the new database layer while acknowledging that `win32` remains held at `5.x` by the current `flutter_secure_storage_windows` dependency chain.

## Client Foundation Completion (v2.24.5 to v2.24.6)

### Flutter Structural Cleanup
- Completed a broad Flutter client refactor so services, controllers, transport helpers, and feature widgets now reflect cleaner ownership boundaries without compatibility bridges, leftover migration shims, or oversized multi-responsibility files.
- Broke major surfaces such as the settings flow, profile hub, dialogs, status/action UI, and transport/update layers into smaller final-shape components that are easier to reason about and maintain.

### Test Realignment Without Compliance Theater
- Reworked the Flutter and terminal-client tests so they target the refactored APIs directly instead of preserving older names or shapes.
- Removed fake compliance constructs from the test suite and kept the remaining test-specific static-analysis accommodations narrow and explicit, preserving readability while restoring stronger behavioral assertions where coverage had drifted.

## Test & Verification Coverage

### Client Validation
- Added and expanded targeted coverage around the new Groq path, including WAV encoding, rate limiting, HTTP error handling, and mode-aware recording/controller behavior.
- Revalidated Flutter client behavior after the Drift migration and structural cleanup so the new storage, transport, and UI boundaries remain exercised through their updated test surfaces.

### Tooling & Quality Gates
- Used the DCM-driven cleanup effort in this range to finish the client-side foundation work rather than to preserve temporary compatibility code.
- Carried the same discipline into the test suite and terminal client so the repository ends this range with a cleaner architectural baseline, not just a quieter analyzer.
