# WhisperDoc Technical Release Notes - v2.23.6
**Version Range: v2.23.2 to v2.23.6**

This release range completes the transition from a single-engine Whisper backend to a **fully pluggable multi-engine platform** with hardened transport behavior, native UV-based packaging, and cleaner operator tooling. Across these versions, the backend was consolidated into a single Docker service that can switch engines via configuration, the WebSocket stack was migrated away from deprecated legacy behavior, the runtime moved to Python 3.12, and the local development workflow was standardized around lockfiles, quality gates, and reproducible environments.

The companion clients were also tightened during this range. The Flutter client now reconnects based on meaningful identity-state changes rather than every auth pulse, and the Python terminal client was upgraded into a UV-managed, typed, testable fallback tool before being explicitly scoped back to its real target: **Windows desktop fallback/debug use**, not Linux/WSL runtime support.

## Infrastructure Consolidation (v2.23.2)

### Single-Service Multi-Engine Docker
- Collapsed the previous two-service Compose layout (`whisper-backend` + `parakeet-backend`) into a single backend service that selects its Dockerfile via `ASR_ENGINE` in `.env`. Engine switching is now a configuration change followed by rebuild, rather than a service topology change.
- Renamed the original backend Dockerfile into `Dockerfile.whisper` and added `Dockerfile.parakeet`, so both engine images follow the same multi-stage pattern while remaining independently tunable.

### Parakeet Image Modernization
- Rebuilt the Parakeet image away from the ~15 GB NVIDIA research container and onto a slim multi-stage Python base, aligning it with the Whisper image’s operational model.
- Upgraded NeMo from `2.1.0` to `2.7.1`, removed the old `numpy<2.0` compatibility pin, and split backend dependencies into shared, Whisper-specific, and Parakeet-specific requirement sets to eliminate the CPU/CUDA torch conflict that previously broke the Parakeet container.

### Initial UV Adoption
- Replaced `pip` with `uv` in Docker and setup flows to accelerate installs and move the project toward a lockfile-driven workflow.
- `setup.sh` and `README.md` were updated to reflect the new engine-selectable Docker path, and the backend HTTP `/transcribe` endpoint began normalizing uploads to `16 kHz` mono WAV via FFmpeg so both engines could share the same ingress path safely.

### Logging & Operational Baseline
- Forced backend timestamps to UTC and added a root-level logging filter as a defensive layer against third-party log noise from the NeMo stack.
- Added tracked audio assets and test fixtures needed for the new multi-engine and HTTP transcription paths.

## Transport Hardening (v2.23.3)

### WebSocket Sans-I/O Migration
- Migrated Uvicorn from the deprecated legacy `--ws websockets` handler to `--ws websockets-sansio` in both backend Dockerfiles.
- This change was made specifically to escape the `websockets.legacy` compatibility wall that appeared with `websockets >= 14`, where Cloudflare Tunnel and modern proxy artifacts could trigger HTTP 400 upgrade failures under the old path.

### Narrower Failure Surfaces
- Tightened `ModelManager.load_model()` so cache-miss fallback only catches the expected filesystem/cache exceptions instead of swallowing all errors and silently dropping into a network download path.
- Removed the stale WebSocket test skip that had normalized transport-level 400s under the old stack. After the migration, a 400 is treated as a real regression again.

### Terminal Transport Diagnostics
- Pinned the terminal client’s `websockets` version to match the backend and avoid independent client-side drift during handshake debugging.
- Expanded terminal connection error handling so failed upgrades surface structured status, headers, and body details instead of a generic “Connection failed” message.

## Runtime Upgrade & Diagnostic Cleanup (v2.23.4)

### Python 3.12 Runtime
- Upgraded both backend images from Python `3.10` to `3.12`, keeping the WebSocket stack on `websockets 16.0` with Sans-I/O and preserving the existing h11 workaround that protects the WebSocket upgrade path from the observed `b" "` corruption issue.

### NeMo Investigation Cleanup
- Removed the temporary `WS_DIAGNOSTICS` infrastructure that had been introduced during the NeMo/transport investigation: conditional diagnostic logging, faulthandler and signal hooks, the dump-stacks endpoint, and the one-off `ws_*.py` diagnostic scripts.
- The release deliberately retains the architectural fixups and the investigation report, but strips out the temporary debugging scaffolding from the runtime.

### NeMo/Lhotse Noise Suppression
- Expanded logging suppression to cover message-content filtering and Lhotse-adjacent handlers directly, which was necessary because some of the noisy manifest output came from bare `logging.info()` calls inside the NeMo chain rather than from a clean namespace boundary.
- Added `PARAKEET_SUPPRESS_STDIO=true` and `LHOTSE_LOGGING_LEVEL=ERROR` defaults to support the cleaner runtime envelope.

## Platform Hardening & Client Workflow Modernization (v2.23.5)

### Backend Transport and Protocol Cleanup
- Tightened reverse-proxy-facing middleware defaults and standardized structured `error_code` handling on the backend so transport failures are easier for both clients to route and explain.
- Updated protocol-enforcement/security tests to assert the explicit “error payload first, close second” contract rather than only checking the close event.

### Flutter Reconnection Refinement
- Refined the Flutter transport fingerprinting logic so reconnects happen on meaningful identity-state changes rather than every auth pulse. This reduces reconnect churn around silent refresh without weakening transport/credential alignment.
- Updated transport tests and docs to reflect that new behavior and to keep the client/backend contract explicit.

### Terminal Client UV + Quality Pass
- Converted the terminal client into a proper UV-managed project with `pyproject.toml`, `uv.lock`, typed transport message boundaries, and significantly expanded automated coverage.
- Preserved `whisper_client.py` as a compatibility shim while standardizing the supported launch flow around UV entrypoints and project-local tooling (`pytest`, `pyright`, `ruff`).

## Native UV Completion & Repository Workflow Tightening (v2.23.6)

### Backend Native UV Migration
- Finished the backend’s transition from split `requirements*.txt` files and `uv pip --target ...` installs to a native UV project defined by `backend/pyproject.toml` and `backend/uv.lock`.
- Docker now installs the backend into an in-image `.venv` via `uv sync`, with explicit extras for `whisper` and `parakeet`, instead of relying on `/root/.local` and custom `PYTHONPATH` assumptions.

### Setup and Environment Flow
- Reworked `setup.sh` into a backend-only setup path that explicitly chooses `whisper` or `parakeet`, syncs the matching backend environment, and updates `.env` accordingly.
- This removes the misleading implication that the Linux setup script is also responsible for provisioning the terminal client runtime.

### Repo-Wide Quality Gates
- Added a repo-level `.pre-commit-config.yaml` that runs Ruff with `--fix` plus `ruff format` separately for `backend/` and `terminal_client/`, using each project’s own `pyproject.toml`.
- Backend test and lint cleanups in this version were focused on making those shared commit-time hooks truthful rather than merely permissive: the repository now auto-fixes what Ruff can repair and fails cleanly when a change still needs manual attention.

### Windows-Only Terminal Client Positioning
- Tightened the terminal client docs and runtime contract so it is now explicitly treated as a **Windows fallback/debug client**.
- Added an early runtime guard that exits unsupported Linux/WSL launches with a clear message instead of falling through to `pynput`/X server failures.

## Test & Verification Coverage

### Backend Validation
- Full backend validation was rerun after the native UV migration landed, including Pyright, the backend pytest suite, both engine-specific Docker builds, and live startup/transcription smoke testing against the Parakeet backend.
- Test seams were preserved intentionally during the lazy import refactor: the patchable module-level `WhisperModel` symbol was restored so existing test strategy and runtime decoupling could coexist cleanly.

### Tooling Verification
- `setup.sh` was manually exercised to verify that backend environment provisioning works end-to-end through the new UV-native path.
- Repo-level pre-commit was exercised against the Python trees to confirm that `ruff --fix` and `ruff format` run in the intended order and block commits when manual intervention is still required.
